Build corpus.json

Regenerates the search index for the Ask page from portfolio.html. Serve the repository (python3 -m http.server 8000) and open this at /scripts/build-corpus.html — it needs real HTTP, because the model files are fetched.

Why this is a page and not a script. The embeddings have to be the ones the shipped code would have produced; a vector that differs from what the browser computes does not raise an error, it just retrieves worse. Running the generator in the same engine, against the same vendored WebAssembly runtime and the same quantised weights, makes that true by construction rather than by comparison. Node was tried first and cannot do it: the vendored build is the web build, its ONNX backend registry is empty outside a browser and its loader resolves model paths through fetch(). A Python generator would need onnxruntime, and AGENTS.md is explicit that this repository does not take on a toolchain.

Press the button, wait for the model to download, then save the JSON over corpus.json at the repository root and commit it.
