# tatangharyadi.github.io: Product Requirements

## What this is

A personal site that is also its own evidence. It is static HTML and CSS served
by GitHub Pages from `main`, with no build step, no bundler and no package
manager, and it carries two pieces of software that would ordinarily need a
server: a semantic search that runs entirely in the visitor's tab, and a trading
simulation compiled to WebAssembly from Rust.

The claim the site makes is not "here is a list of roles". It is "here is work
you can read, run and check". Every non-obvious assertion on the site is either
generated from a source of truth or held in place by a script in `scripts/` that
fails CI when the assertion drifts. That arrangement is the product.

For how the site is built and why, read [ARCHITECTURE.md](../ARCHITECTURE.md).
For the rules that bind a change, read [AGENTS.md](../AGENTS.md).

## Architecture overview

```
index.html ────────── htmx ──────── fragments/work/*.html
   │                                        ▲
   │                                        │ generated by
   │                                 scripts/propagate_work.py
   │                                        │
   │                                 portfolio.html  (source of truth for prose)
   │                                        │
   │                                        │ generated by
   │                                 scripts/build-corpus.html  (in a browser)
   │                                        ▼
   └── js/ask.js ──── vendor/transformers ── corpus.json      → F01_ASK
                          + assets/models/

game.html ─── js/game.js ─── assets/game.wasm  ← cargo, wasm32-unknown-unknown
                                    ▲
                                    │ compiled from
                             game/src/*.rs                     → F02_GAME
                                    ▲
                                    │ world.rs generated by
                             scripts/gen_game_data.py ← game/data/*.tsv

mocap.html ─── js/mocap.js ──┬── vendor/litert ── assets/models/pose-landmark-full/
              │            │        (BlazePose pose inference)     → F03_MOCAP
              │            └── vendor/three ─── assets/character/RobotExpressive.glb
              └── js/mocap-retarget.js  (landmarks → bone quaternions)
```

Three properties hold across the whole diagram:

- **The arrow always points away from a single source.** Prose lives in
  `portfolio.html` and reaches fragments and the search index by generation, never
  by hand. The map lives in `game/data/*.tsv` and reaches Rust by generation.
- **Every generated artifact has a `--check` mode.** `propagate_work.py`,
  `gen_game_data.py`, `check_corpus.py` and `build_game.sh` all run in CI and fail
  on drift.
- **The visitor's toolchain is empty.** A contributor editing prose needs Python
  and a browser. Only someone changing the simulation needs Rust, and even then
  the committed binary means nobody else does.

## Features

### F01: Ask → [F01_ASK.md](F01_ASK.md)

Semantic search over the portfolio, executed in the visitor's browser.

- A question is embedded with `all-MiniLM-L6-v2` (8-bit quantised, 384
  dimensions) and scored by cosine similarity against pre-computed vectors in
  `corpus.json`.
- **Nothing is sent anywhere.** There is no endpoint, no key and no log. The
  privacy property is structural rather than promised: the question never leaves
  the tab because there is nowhere for it to go.
- The model and runtime are a large download, so the feature is gated behind an
  explicit button that states the cost before spending it, with a progress bar
  while it loads.
- `corpus.json` is generated from `portfolio.html` by
  `scripts/build-corpus.html`, a page rather than a script, because the vectors
  must be the ones the shipped code would produce.
- `scripts/check_corpus.py` asserts every indexed passage is still on the page,
  every anchor resolves, and the model and dimension count still match.
- The one failure no static check can catch is prose added and never indexed. The
  human step for that is written into AGENTS.md.
- It is one of exactly two JavaScript files of our own, and the exception is
  argued: every other interaction on the site is a request for HTML, and this one
  is not.

### F02: Helm → [F02_GAME.md](F02_GAME.md)

An age-of-sail trading simulation on a hexagonal world map, reached as an easter
egg from the masthead.

- The simulation is Rust compiled to `wasm32-unknown-unknown` with no
  `wasm-bindgen` and no `wasm-pack`. Exports are `extern "C"` over `i32`; strings
  cross as UTF-8 in linear memory. The binary imports nothing at all.
- `js/game.js` is a boundary and a renderer, nothing more. It instantiates the
  module, calls exports, reads bytes back and draws SVG. No rule lives in it.
- Trading, ships, crew, provisioning, reputation, pursuit and commissions are all
  simulation-side and covered by tests that run on the host, not in a browser.
- The world map is generated from TSV, and the generator asserts the map is
  playable: no two ports in one hex, every port with land adjacent, and every port
  reachable by sea.
- This is the only place on the site that breaks the no-build-step rule. It is
  quarantined into a separate page, stylesheet, script and language, and the
  committed binary keeps the toolchain off everyone else's path.

### F03: Echo → [F03_MOCAP.md](F03_MOCAP.md)

A webcam-driven pose demo, reached as an easter egg from the other linked word
in the masthead role.

- MediaPipe's BlazePose, run through Google's LiteRT.js, turns each video frame
  into 33 body landmarks entirely in the visitor's browser. Nothing is
  uploaded, for the same structural reason Ask's question never is.
- `js/mocap.js` is a boundary and a renderer, in the same shape as `js/game.js`:
  camera acquisition, model load, inference loop, Three.js scene.
  `js/mocap-retarget.js` is not a boundary — turning a landmark into a bone
  rotation is a rule, so it is argued on its own terms in F03_MOCAP.md rather
  than folded into the boundary framing.
- Only the two non-threaded LiteRT WASM builds (`compat_internal`,
  `internal`) are usable, because GitHub Pages cannot set the COOP/COEP
  headers cross-origin isolation needs — the same constraint `js/ask.js`
  already lives under.
- One character (`RobotExpressive.glb`, CC0), body pose and head/neck
  orientation — lateral lean and yaw, not nodding or in-place tilt, a real
  scope cut and not yet a fully solved feature. No recording or export. Scope
  cuts are listed in full in F03_MOCAP.md.
- Status: wired end to end and verified in a browser — camera access, pose
  inference, retargeting, rendering and a stop/restart cycle all confirmed
  working. Four gaps found and fixed via synthetic landmarks in a loaded
  browser tab (mirrored L/R mapping, excess Neck pitch from depth noise, a
  static offset baked into the Head bone, and unsupported head yaw, fixed as
  a twist applied to Head separately from Neck's swing math). A real camera
  then took five more passes to make that yaw fix usable, all five rooted in
  noise or drift in the same ear-depth-difference signal: it froze on losing
  the far ear's tracking mid-turn and snapped between left/right with no
  damping (fixed with fallback-to-front on lost tracking and a per-frame
  slerp); then defaulted to a left turn facing the camera dead on, because
  the raw signal never read zero at rest (fixed by calibrating an early
  reading as "forward" and measuring later frames as a delta from it); then
  overcorrected the other way, because that calibration locked onto a single
  frame no less exposed to noise than the signal it corrected (fixed by
  averaging 30 tracked frames before locking the baseline in); then
  oscillated left/right without settling, because the signal's sign was
  flipping frame to frame near zero and no output-side damping can converge
  on a target that itself keeps reversing (fixed by low-pass filtering the
  signal itself, `DEPTH_DIFF_FILTER_ALPHA`, before the deadzone and sign
  check see it); then read as one turn direction saturating the clamp while
  a comparably deliberate turn the other way barely cleared the deadzone,
  because the locked baseline had drifted away from where the signal
  actually rested partway into the session rather than any real per-ear bias
  (fixed by letting the baseline keep drifting slowly toward the tracked
  signal, `BASELINE_DRIFT_ALPHA`, instead of locking it once for the whole
  session). All five fixes are re-verified synthetically against sequences
  built to reproduce each reported symptom, and the fifth is also reconfirmed
  on a real camera. The rest of the human
  verification steps in AGENTS.md (keyboard traversal, both colour schemes,
  breakpoints, reduced motion, Lighthouse, and that real-camera pass) have
  not yet been run.

## Verification

There is no test suite for the site itself. The mechanical invariants are checked
in CI and the rest is checked by a person in a browser, which is deliberate:
**a green CI does not mean a change is verified.**

| Check | Guards | Where |
| --- | --- | --- |
| `check_htmx.py` | Fragments resolve, agree with `portfolio.html`, keep focus ids | CI |
| `propagate_work.py --check` | Fragments are exactly what the generator emits | CI |
| `check_corpus.py` | The search index still describes the page | CI |
| `check_palette.py` | The palette agrees across all five copies | CI |
| `check_repo.py` | `.nojekyll` present, nav in step, sitemap in step | CI |
| `gen_game_data.py --check` | `world.rs` is freshly generated and the map is playable | CI |
| `build_game.sh --check` | The committed wasm matches its recorded hash | CI |
| design.md lint | `DESIGN.md` conforms, at zero errors and zero warnings | CI |
| `cargo test` | The simulation's rules | CI |
| Keyboard traversal | Every control reachable, focus never lands on `<body>` | Human |
| Both colour schemes | Mocha and Latte both correct | Human |
| Breakpoints and reduced motion | 1200 / 850 / 750px, `prefers-reduced-motion` | Human |
| Lighthouse, once per scheme | Accessibility, Best Practices and SEO at 100 | Human |
| Passage count went up | Prose added to `portfolio.html` was actually indexed | Human |

## Non-functional requirements

| | |
| --- | --- |
| **Accessibility** | Lighthouse Accessibility 100 in both schemes. Nine invariants in AGENTS.md are load-bearing, including: no use of the `disabled` property anywhere, stable ids across every htmx swap, and `role="list"` retained on unmarked lists. |
| **Contrast** | Text at or above 4.5:1 and graphical marks at or above 3:1, measured against Latte, which is always the tighter flavour. Measurement composites real declarations onto a canvas and reads pixels. Compositing on paper is not accepted as evidence. |
| **No third-party runtime the site does not pin** | htmx arrives from a CDN pinned by version and SRI digest. There is no webfont and no icon font. Every glyph is inline SVG. |
| **Works with no JavaScript** | The work index degrades to ordinary links. `portfolio.html` carries the full prose and is crawlable. Ask states its requirement in `<noscript>`. |
| **No build step** | Except `game/`, which is the single argued exception. |
| **Privacy** | No analytics, no cookies, no third-party beacons. Search runs client-side by construction. |

## Out of scope

- A backend of any kind. Adding one would dissolve the property F01 exists to demonstrate.
- A bundler, framework or package manager to solve something a few lines of CSS solve.
- A JavaScript file of our own without an argument made from scratch. Four
  exist now (`js/ask.js`, `js/game.js`, `js/mocap.js`, `js/mocap-retarget.js`)
  and each is argued individually in AGENTS.md; a fifth needs its own case,
  not an appeal to precedent.
- A comment system, newsletter or analytics.
- Reproducible wasm builds. The committed hash proves the binary has not changed
  since it was committed, and does not prove it is what `game/src` compiles to.
  That limit is stated in the script's own header.

## Deferred

| Item | Why it is not done |
| --- | --- |
| A way to make contact | The site has no `mailto:`, no contact section and no availability line. This is the highest-value open gap. |
| Reducing the Ask download | The weights are the great majority of the transfer. A smaller model or a served-once index would change the retrieval quality, so it needs measuring before it is chosen. |
| Surfacing the easter eggs | Discovery of either linked masthead word is close to zero. A single colophon sentence linking them is proposed and unresolved. |
| Repo-wide em dash strip | Prose style is inconsistent across the Markdown files. One follow-up change, no behaviour. |
